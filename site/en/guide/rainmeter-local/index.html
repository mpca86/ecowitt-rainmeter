STEP 1

Install the Local source skin

First install Rainmeter. The main-branch Local API is provided as source code; the current documentation does not establish a public standalone Local .rmskin release.

1

Prepare Rainmeter

Install Rainmeter from its official website ↗ on Windows and open its skin manager.

2

Download the main branch

Download the main branch ZIP ↗ from GitHub and extract it. Locate src/EcowittWeather/, which includes Meteo, Settings, Diagnostics and @Resources.

3

Copy the complete folder

Copy the entire EcowittWeather folder to Rainmeter's Skins directory (often Documents\Rainmeter\Skins; check your actual configured location). Preserve the full tree, including @Resources.

Not the Cloud installer: the public v1.11.0-beta.6.rmskin uses Ecowitt Web API v3. Do not install that package for this Local procedure; follow the main branch source instructions instead.

STEP 2

Find your gateway and test JSON

You need a compatible Ecowitt gateway exposing the local HTTP endpoint. A wireless sensor on its own is not a gateway.

NETWORK

IP address and reachability

Find your gateway's IP in your router's DHCP device list. Your PC must be able to reach it over the LAN or an appropriate VPN. Check Wi-Fi client isolation, VLAN routing and firewall policies.

  • Example IP: 192.168.1.50 – illustrative only
  • Default port in Variables.inc: 80
  • This is the gateway IP/port, not your ecowitt.net account
JSON ENDPOINT

Test from your browser

On the same Windows PC, open:

http://192.168.1.50:80/get_livedata_info

Replace IP and port with the actual gateway details. A compatible gateway should return JSON. The existing Rainmeter connection test searches the response for common_list and debug.

Security: this uses unencrypted http:// within a private network. Do not expose the endpoint using internet port forwarding; use a secure VPN if remote access is required.

STEP 3

Configure Rainmeter and test the gateway

The Local skin does not need Application Key, API Key or station MAC. It uses a gateway IP/hostname and a separate port.

1

Open the Settings skin

Refresh the Rainmeter skin list and load EcowittWeather\Settings\Settings.ini. The panel is titled ECOWITT WEATHER – NASTAVENIA (Settings).

2

Enter Gateway address and Port

Enter only the IP address or hostname in Gateway address, without http:// or the port. Enter 80 (or your gateway's port) in the separate Port field. Press Enter after each field.

3

Test and open METEO

Click TEST PRIPOJENIA (test connection). If the expected response matches, Settings displays Pripojené – Local API odpovedá. Otherwise it warns about host, port or routing/firewall. Then click OTVORIŤ METEO SKIN (open weather).

Version-specific storage: this Settings skin writes into @Resources/Includes/Variables.inc. Back up your personal configuration before replacing source files.

STEP 4

Readings, channels and history

The Local skin uses Rainmeter WebParser, a JSON decoder and a generic Ecowitt parser. Only fields returned by the gateway can be shown.

METEO

Available measurements

Outdoor/indoor temperature and humidity, wind, UV, solar irradiation, rainfall and pressure. Available CH1–CH8 sensors are handled dynamically; absent channels are hidden.

Aliases Channel1Label to Channel8Label and GatewayLabel can be edited in Variables.inc.

HISTORY

Local CSV and trends

While METEO runs, sample history is stored in Meteo/meteo_history.csv. Implemented calculations include 15-minute temperature trends and 3-hour pressure tendency.

Initially there may be too few history samples to calculate trends. This is a local CSV file, not a Cloud export.

STEP 5

Diagnostics and troubleshooting

If the endpoint fails in your browser, troubleshoot network or gateway compatibility first. If JSON works but METEO does not, inspect Rainmeter.

CONNECTIVITY

Common failures

  • No response: verify the IP, port, gateway power and connectivity from PC to gateway.
  • HTTP error/timeout: check VLAN routing, Wi-Fi isolation, firewall, VPN path or endpoint support.
  • JSON loads but test fails: verify whether the response has the expected common_list and debug fields.
  • Empty METEO panel: check that Meteo.ini is loaded, the parser receives valid values and sensors are connected.
PARSER DEBUG

Diagnostic file

In @Resources/Includes/Variables.inc, temporarily change DebugParser=0 to DebugParser=1, refresh METEO and wait for a valid sample.

Then load Diagnostics/Diagnostics.ini using the Rainmeter manager or open @Resources/Diagnostics/ecowitt_debug.txt. Set DebugParser=0 again afterwards.

Unlike the Cloud beta, the main-branch Settings panel has no DIAGNOSTIKA button. Load the Diagnostics skin separately. Check logs for private local network, station and sensor names before sharing.

EDITION CHOICE

Local, Cloud and Desktop are different

Avoid mixing the installation instructions or connecting to the wrong data source.

RAINMETER LOCAL

Main-branch source baseline

Manual installation, LAN/VPN, EcowittHost and EcowittPort; no Ecowitt Application Key, API Key or station MAC. No Ecowitt Web API request is needed to retrieve local measurements.

FAQ

Frequently asked questions

Check your local endpoint and connection-test result before making parser changes.

Do I need an ecowitt.net account or API credentials?

Not for this Local Rainmeter source baseline. It makes direct HTTP requests to the gateway over LAN/VPN; Cloud API keys and station MAC do not belong in these Settings.

Where can I download a Local .rmskin installer?

The current main branch documentation does not confirm a separate public Local .rmskin release. Use manual source folder installation as described here.

Why does TEST PRIPOJENIA report no response even when JSON loads?

The current main test looks for common_list and debug in the response text. A gateway returning a different JSON schema might not pass the test; the parser may also be incompatible.

Do I need internet access?

Internet is not required for measurements if the Rainmeter PC and gateway can communicate over LAN/VPN. Internet is needed initially to download Rainmeter and the source code.

Where are settings and history saved?

Configuration is in @Resources/Includes/Variables.inc and local history in Meteo/meteo_history.csv. Back them up before manually replacing files.

My PC and gateway are on different VLANs. What now?

Enable necessary routing and firewall permissions for the gateway's port and remove client isolation where appropriate. Do not forward the local HTTP endpoint directly to the internet.
