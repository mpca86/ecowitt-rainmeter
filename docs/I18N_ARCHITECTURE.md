# Cloud API Rainmeter i18n plan — SK / EN / CS / PL

Status: **P2 runtime wiring implemented / clean-install fallback Windows QA pending**.
This test branch is based on `test/cloud-api-beta7-integration`. It is independent of the UTF-16 Lua
packaging fix in draft PR #27; integrate that fix before a future beta release.
No merge or release is authorized by this document.

## Supported interface languages

| Code | End-user name | Initial fallback |
| --- | --- | --- |
| `sk` | Slovenčina | as selected |
| `en` | English | **default fallback** |
| `cs` | Čeština | as selected |
| `pl` | Polski | as selected |

Until i18n is deployed, beta.6 continues using Slovak. In the new version,
**`UiLanguage=auto` is the default**; it reads the `Language` LCID from
`[Rainmeter]` in the user's `#SETTINGSPATH#Rainmeter.ini` (not the Windows
system display language). Resolution priority is manual `sk`/`en`/`cs`/`pl`,
then a present `Rainmeter.ini` LCID, then Rainmeter's installer registry value
only when the INI key is absent, and finally **`en`**. LCIDs 1051 SK, 1033 EN,
1029 CS, and 1045 PL are mapped by Windows primary-language bits. A present
but invalid or unsupported INI value resolves to `en` and never falls through
to a possibly stale registry value. Store only the `UiLanguage` preference in the existing
`@Resources/Includes/UserVariables.inc`; never modify Rainmeter.ini or
`CloudSecrets.inc`, and retain aliases, API keys and CSV history.

## Localization inventory — source audit

- `Meteo/Meteo.ini`: outdoor/wind/solar/UV/rainfall labels, UV severity, update
  tooltips, missing credentials. Dynamic cloud status and rain labels are
  generated by `@Resources/Scripts/main_cloud.lua`; wind directions are also
  generated there.
- `Settings/Settings.ini`: titles, hints, sensor/diagnostics/update buttons,
  transfer/export/import warnings, Cloud API test UI, upcoming language selector.
- `Sensors/Sensors.ini`: header, user help, navigation and gateway caption.
  **Custom CH1–CH8 and gateway names are user data, not translations.**
- `Diagnostics/Diagnostics.ini`: debug state explanation, actions and navigation.
  Content of the generated debug log is not yet localized.
- `Update/Update.ini`: update status, channel, version, changelog and actions;
  `Substitute` uses hard-coded Slovak text.
  `updater.ps1` and `test-cloud-api.ps1` also return user-facing messages.
- External GitHub release notes/changelog and raw Ecowitt API error messages are
  external data, not translated by this initial catalog.

The evolving catalog inventories **85 interface concepts** in each locale, including the automatic-language option.
The catalog coverage is **NOT yet a guarantee that all user-visible text is
wired to translations**; remaining runtime strings will be migrated in P2.
Fields with `{count}`, `{channel}`, `{time}`, `{version}`, and
`{message}` use named placeholders, validated across all four languages.

## Architecture (implementation stages)

1. **P1: source catalogs and compiler (this branch).** Keep source dictionaries
   in `packaging/i18n/catalogs/{sk,en,cs,pl}.json` (UTF-8). Validate identical
   keys, exact placeholder sets, safe Rainmeter values and variable-name
   collisions. `packaging/i18n/compile.py --output <staged skin
   root>/@Resources/Languages` emits `sk.inc`, `en.inc`, `cs.inc`,
   `pl.inc` as **UTF-16 LE with BOM**, leaving Git sources untouched.
2. **P2: Rainmeter runtime wiring (implemented on the test branch).** Settings
   offers `auto`, `sk`, `en`, `cs`, and `pl`, saving only the preference to
   `UserVariables.inc`. The Lua bootstrap stores a safe,
   **allowlisted effective language** separate from the `auto` preference;
   never interpolate unchecked strings into an include path. After
   `Variables.inc` and `UserVariables.inc` have loaded, each panel may
   include a language file in `@Resources/Languages`; confirm the
   resolution timing and refresh behavior in Rainmeter 4.5 before shipping.
   Replace static labels with
   `#L_...#`, map UV/wind enums to translated labels, and translate
   Lua-generated status and rainfall using the selected catalog. Refresh
   all five panels when switching language, retaining user input.
3. **P3: full localization and QA.** Cover user-visible messages from
   PowerShell update/check/import/test actions without changing their
   protocol outputs (e.g., `UPDATE|version`). Verify clipping,
   diacritics, Polish/Czech characters, changing a language mid-session,
   missing/invalid locale fallback, Cloud beta update and rollback.
   Preserve secret files and local history across a new RMSKIN install.
4. **P4: separate beta release approval.** Only after PR #27 and i18n are
   reviewed/merged and Windows QA passes, request approval for beta.7.
   Do not update `packaging/RELEASE_VERSION`, trigger
   `release:` commits or invoke the release workflow during P1.

## Build/encoding rules

Rainmeter's non-ASCII INI/include strings require UTF-16 LE with BOM.
`main_cloud.lua` is Unicode-sensitive; use the staged conversion from
PR #27 **before** packaging. Do not silently convert or rewrite the source
INI files, API secrets or user settings in this foundation branch.
The P1 compiler writes only into an explicit `--output` destination.

Commands to validate the dictionaries without writing files:

```sh
python3 packaging/i18n/compile.py
```

Build UTF-16 includes into an isolated test directory:

```sh
python3 packaging/i18n/compile.py --output /tmp/ecowitt-i18n/Languages
```

These outputs do not yet enable the language selector or localize installed
beta.6. That requires the explicit P2 runtime work and a Windows test.

## P2 runtime implementation (prepared; Windows QA pending)

- All five Rainmeter panels now load `@Resources/Includes/LanguageState.inc`
  (UTF-16 LE), English fallback, and selected language include using
  `#ResolvedUiLanguage#`, which is **allowlisted** by
  `@Resources/Scripts/language_bootstrap.lua`.
- Startup reads Rainmeter's `#SETTINGSPATH#Rainmeter.ini` (`[Rainmeter]`
  `Language` LCID) without modifying it. If that key is absent, built-in
  Rainmeter Registry measures read `HKLM\SOFTWARE\WOW6432Node\Rainmeter` or
  `HKLM\SOFTWARE\Rainmeter`, selected by the Rainmeter process architecture.
  The Lua bootstrap waits for its selected measure before resolving. A present
  malformed or unsupported INI value resolves to English without registry
  fallback. The automatically selected locale
  refreshes active panels only after writing the locale state, with no refresh
  when the locale is unchanged. A missing registry value also resolves to `en`.
- Settings has an `AUTO / SK / EN / CS / PL` row. Clicking a choice writes
  `UiLanguage` to `UserVariables.inc`, reloads Settings, and the bootstrap
  refreshes the remaining panels if the **effective** locale changes.
- METEO, Sensors, Settings, Diagnostics and Update use translated catalog
  variables, including UV severity, rain labels, status age and wind direction.
- `src/EcowittWeather/@Resources/Languages/{sk,en,cs,pl}.inc` are checked-in
  UTF-16 LE compiled includes. The source JSON remains editable UTF-8.
- A test-only ZIP overlay in Actions copies only public files and stages
  `main_cloud.lua` to UTF-16 LE (the behavior required by separate PR #27).
  The ZIP is **not** a beta release and must not be used without backups.
- **Pending:** real Windows Rainmeter tests of first-load auto detection,
  manual switching, unsupported locales, Polish / Czech clipping,
  diagnostics/update controls, alias persistence, portable settings,
  and actual installer upgrade / rollback. Full human-language translation
  of raw PowerShell / external API diagnostics is not yet implemented.

## Automatic language resolution tests

The Lua regression test mocks Rainmeter's `SKIN` API and covers manual
overrides, SK/EN/CS/PL LCIDs, missing/invalid/unsupported INI values, stale
registry values, deferred Registry measure startup, registry-view selection,
restart behavior, and refresh idempotence. The read-only PowerShell resolver
also retains its standalone regression test:

```powershell
pwsh -NoProfile -File packaging/i18n/tests/test-resolve-language.ps1
```

The automated tests do not replace Windows Sandbox verification with the
test-only RMSKIN; first-run AUTO behavior and the native / WOW6432Node registry
views still require manual confirmation there.
